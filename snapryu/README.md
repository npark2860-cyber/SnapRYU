# SnapRYU 1.0

Windows ARM64와 Qualcomm Adreno 환경을 위한 Eden 기반 Nintendo Switch 에뮬레이터입니다. 기존 Eden/yuzu의 CPU·GPU 구현을 바탕으로, 이 장치에서 확인한 렌더링·동기화 문제와 NCE 실행 경로를 수정합니다.

이 폴더에는 정상 동작 기준, 새 소스, 빌드 도구, 검증 기록이 함께 있습니다. 정식판은 `bin/SnapRYU.exe`, 진단판은 `bin/SnapRYU-Diagnostic.exe`로 구성합니다. 두 실행 파일은 같은 포터블 프로필과 NPU 파일을 사용하므로 한 번에 하나만 실행합니다. 최종 실행 파일 해시와 검증 결과는 `reports/build-result.json`에 기록합니다. 빌드 성공과 실제 게임 플레이 검증은 구분합니다.

## Eden에서 달라진 점

| 영역 | SnapRYU 변경 |
|---|---|
| Adreno Vulkan | 현재 작업의 셰이더·렌더링 호환 수정 유지 |
| 조건부 렌더링 | CPU 판정에 필요한 GPU 결과의 완료와 게스트 메모리 게시를 기다림. 일반 Immediate 통지를 실제 완료로 오인하지 않음 |
| 상수 버퍼 수명 | 아직 처리하지 않은 명령이 필요한 값을 CPU가 재사용하기 전에 보존. UB_KEEP R2의 unmap 처리·보호 순서 유지 |
| 캐시 정합성 | dirty 수집 경쟁, 취소된 다운로드 재등장, 더 최신 GPU 소유권 삭제 방지 수정 유지 |
| Windows NCE | 가상 x18·FPCR 처리와 기존 정체 구제 동작 유지. 후속 Eden의 exclusive 명령 판별 수정 포함 |

| 성능 표시 | 작은 FPS·프레임 시간·CPU%·GPU%·NCE/Dynamic 패널 |
| 빌드 구분 | 기본 로그를 남기는 정식판과 조사 계측을 사용할 수 있는 진단판 |

## 기능 사용

**Zelda: Tears of the Kingdom 고정 1080p**는 게임별 그래픽 설정에서 켭니다. 지원 범위는 게임 버전 1.4.2, 타이틀 `0100F2C0115B6000`, 소스에 고정된 빌드 ID입니다. 게임을 다시 시작해야 적용됩니다. 해상도 배율은 1×에서 먼저 확인합니다. 지원하지 않는 실행 파일이나 충돌하는 ExeFS/치트 패치가 있으면 적용하지 않습니다. 1080p 켜짐은 강제 종료 해결을 보증하는 설정이 아닙니다.

**NPU 프레임 생성**은 Vulkan의 그래픽 고급 설정에서 OFF / ON (Auto) / 2X로 선택합니다. 게임을 종료한 상태에서 설정하고 다시 시작해야 적용됩니다. Auto의 기본 목표는 60FPS이며 최대 2배까지만 생성합니다. 두 원본 사이의 중간 프레임 한 장을 만들며, 같은 이미지를 반복해 생성 프레임으로 세지 않습니다. 생성 처리는 1280×720에서 수행하고 원본 프레임은 원래 출력 해상도를 유지합니다. 처리 지연·장면 전환·초기화 실패에는 원본으로 복귀합니다. 원본을 잠시 보관하는 방식이므로 입력 표시 지연이 추가됩니다. 기존 LSFG와 동시에 사용하지 않습니다.

NPU 설정의 기본값은 OFF이며, 변경 후 게임을 다시 시작해야 합니다. 이전의 3X/4X 설계는 이번 구현 범위에 포함되지 않습니다.

NPU에는 이 패키지의 ORT 1.24.4 / QNN 런타임과 해당 장치의 Qualcomm NPU 드라이버가 필요합니다. `npu/runtime/rpc-path.txt`는 이 장치에 설치된 드라이버의 `libcdsprpc.dll` 경로입니다. 다른 PC로 옮기거나 드라이버가 갱신되면 해당 경로를 다시 확인해야 합니다. 드라이버 DLL을 Windows 폴더에 덮어쓰지 않습니다. 모델 세션이 준비됐다는 것과 실제 생성 프레임이 표시됐다는 것은 서로 다른 상태입니다.

**성능 표시창**의 FPS는 게임이 만든 원본 프레임 수입니다. CPU%는 이 프로세스가 전체 논리 CPU 용량 중 사용하는 비율이고, GPU%는 이 프로세스의 가장 바쁜 Windows GPU 엔진 값입니다. 프레임 시간은 에뮬레이터 작업 시간이며 GPU 시간만을 뜻하지 않습니다. CPU/GPU는 약 1초마다 수집하고 제공되지 않는 값은 `--`로 표시합니다. 패널은 드래그로 이동합니다.

표시창은 보기 메뉴의 `Show Performance Overlay`에서 켭니다. 처음에는 기존 프로필의 표시 여부를 그대로 따릅니다.

## 데이터와 로그

실행 파일 옆 `user` 폴더가 있으면 포터블 모드로 사용합니다. 없으면 `%APPDATA%/SnapRYU`를 사용합니다. 기존 Eden의 데이터 폴더를 자동으로 이동하거나 삭제하지 않습니다. 현재 장치 시험용 프로필은 원본을 보존한 복사본으로 준비합니다. 세이브·키·펌웨어·게임 파일은 공개 배포물에 포함하지 않습니다.

포터블 모드의 기본 로그는 `bin/user/log/snapryu_log.txt`이며, `user` 폴더가 없으면 `%APPDATA%/SnapRYU/log/snapryu_log.txt`입니다. 정식판에서는 조사용 CGT와 상세 비용 계측을 빼고, 시작·오류 등 기본 로그는 남깁니다. 진단판은 같은 기능과 수정에 추가 계측을 제공하며, 무거운 기록은 명시적으로 켜야 합니다. 진단 로그가 게임 타이밍에 영향을 줄 수 있습니다.

이 장치용 `bin/user`는 기존 시험 프로필의 복사본이며 개인 키·펌웨어·세이브를 포함합니다. 이 폴더를 배포 파일에 넣지 마세요. 원본 프로필은 그대로 보존됩니다.

## 빌드와 출처

이 장치의 MSYS2 clangarm64, CMake/Ninja와 기존 의존성 캐시를 사용하는 `tools/build.ps1`가 있습니다. `-Diagnostic`을 지정하면 별도 진단 출력에 빌드합니다. 두 빌드는 `source`를 공유하며 `SNAPRYU_DIAGNOSTICS`로 조사 계측을 구분합니다.

- `baseline`: 사용자 확인을 받은 UB_KEEP R2 실행 파일·manifest·소스 해시.
- `source`: 해당 R2를 출발점으로 한 SnapRYU 소스.
- `reports/EXPERIMENTS-CONSOLIDATED.txt`: 실험 100개와 최신 판정의 통합 기록.
- `reports/experiment-index.json`: 원문 215개·실행 205개·빌드 73개의 근거 색인.
- `reports/UPSTREAM-REVIEW.txt`: Eden 후속 변경의 채택·보류 판단.
- `planning/status.json`, `planning/HANDOFF.txt`: 단계별 진행과 인계 정보.

기존 UB_KEEP R2에 대한 사용자의 조명·튐·멈춤 확인은 기준판의 결과입니다. 새 기능을 합친 SnapRYU의 전체 게임 호환성과 성능은 별도 플레이 검증이 필요합니다. 과거 NPU 단독 측정의 약 17.86ms 중앙값은 게임 캡처·업로드·표시·경합을 포함하지 않으므로 게임 성능 수치로 사용하지 않습니다.

## 이번 빌드의 검증

- 정식판·진단판 모두 네이티브 ARM64 빌드 및 메인 창 시작·정상 종료 확인.
- 진단판 최종 1080p·버퍼·Vulkan 검사: 9개 테스트, 9,250,822개 검증 통과.
- UB_KEEP 독립 검사: 정식 8,265개, 진단 8,276개 검증 통과.
- 실제 Qualcomm HTP에서 NPU 엔진 187개 및 동시성·작업 제한 34개 검사 통과.
- 정식 EXE에서 CGT·상세 비용·판정 대기 추적 문자열 제거 확인. 진단판은 CGT 유지.
- 새 빌드의 게임 플레이, NPU의 실제 Vulkan 화면 출력과 게임 성능은 아직 확인하지 않음.

실험 덤프 245개, 96,290,956,566바이트를 정리했습니다. 정리 근거는 `reports/cleanup-result.json`에 있습니다. 알려진 정상 기준인 R2 실행 파일과 원본 프로필은 보존했습니다. 개발 중간 산출물 `baseline/SnapRYU-pre-npu.exe`는 빌드 비교용이며 정상 기준판으로 사용하지 않습니다.

SnapRYU는 Eden과 yuzu의 파생 프로젝트이며 원저작자 표시와 GPL 라이선스를 유지합니다. 상위 프로젝트의 GPL 본문은 `LICENSE.txt`, 라이선스 형식은 `LICENSES`에 함께 보관합니다. 개발 폴더의 `source`에는 기존 저작권 표시가 남아 있습니다. 현재 패키지는 이 장치의 로컬 시험용이며, 추가 NPU 런타임·모델의 배포 문서와 의존성별 고지는 별도 정리가 필요합니다. 제품 이름을 바꾸더라도 기여 출처와 저작권 표시는 지우지 않습니다.
